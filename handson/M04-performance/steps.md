## パート 2: 思考連鎖推論（Chain-of-Thought）（15分）

### ステップ 2.1: 基本的な CoT の実装

```bash
python3 chain_of_thought.py
```

以下のパターンを実装します：

**線形 CoT**: ステップバイステップで推論
```
ステップ1 → ステップ2 → ステップ3 → 結論
```

**分岐 CoT**: 条件に応じて推論パスが分岐
```
分析 → 条件A? → パスA → 結論A
         └─ 条件B? → パスB → 結論B
```

**反復 CoT**: 自己検証ループ
```
推論 → 検証 → 修正 → 再検証 → 確定
```

### ステップ 2.2: 複雑な問題の分解

金融リスク評価シナリオで CoT を適用：
1. 問題の構造化（入力データの整理）
2. 各要素の個別分析（リスク因子の評価）
3. 要素間の関係性分析（相互作用の検討）
4. 統合判断（総合リスクスコアの算出）
5. 検証（矛盾チェック）

### ステップ 2.3: エラー処理と検証の実装

推論連鎖におけるエラー検出パターン：
- 論理的矛盾の検出
- 情報不足の識別と追加質問の生成
- 信頼度スコアの付与

## パート 3: プロンプトフローとオーケストレーション（15分）

### ステップ 3.1: プロンプトフローの設計

```bash
python3 prompt_flow_demo.py
```

マルチステップワークフローを構築：

**カスタマーサポート フロー:**
1. **分類ノード**: 問い合わせカテゴリの自動判定
2. **ルーティング**: カテゴリに応じた専門プロンプトへ転送
3. **処理ノード**: 専門的な回答を生成
4. **検証ノード**: 回答品質のチェック
5. **出力**: 構造化された回答の返却

### ステップ 3.2: 条件付きロジックの実装

動的プロンプト選択のデモ：
- 入力の言語を自動検出 → 適切な言語で応答
- クエリの複雑度を判定 → 簡易回答 or 詳細分析
- 顧客ティアを確認 → サービスレベルに応じた対応

### ステップ 3.3: A/B テストフレームワーク

プロンプトの効果を比較測定：
- バリアント A: 現行プロンプト
- バリアント B: 改善版プロンプト
- メトリクス: 応答品質スコア、レイテンシー、トークン効率
