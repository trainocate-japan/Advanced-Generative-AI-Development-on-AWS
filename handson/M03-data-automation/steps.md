## パート 1: ナレッジベースのセットアップ（20分）

### ステップ 1.1: サンプルドキュメントの準備

```bash
cd ~/handson/M03-data-automation

# サンプル法律文書を S3 にアップロード
aws s3 mb s3://legal-kb-demo-$(aws sts get-caller-identity --query Account --output text)
aws s3 cp sample-docs/ s3://legal-kb-demo-$(aws sts get-caller-identity --query Account --output text)/documents/ --recursive
```

サンプルドキュメント（`sample-docs/`）には以下が含まれます：
- `contract_template.txt` - 契約書テンプレート
- `privacy_regulation.txt` - 個人情報保護規制ガイドライン
- `employment_law.txt` - 労働法の概要
- `ip_guidelines.txt` - 知的財産権ガイドライン

### ステップ 1.2: Bedrock ナレッジベースの作成

AWS コンソールまたはスクリプトでナレッジベースを作成します：

```bash
python3.12 setup_knowledgebase.py
```

スクリプトは以下を実行します：
1. S3 データソースの設定
2. 埋め込みモデルの選択（Titan Embeddings V2）
3. チャンキング戦略の設定
4. ベクトルストアの自動プロビジョニング
5. データソースの同期（Sync）開始

### ステップ 1.3: チャンキング戦略の比較

3つのチャンキング戦略を設定し、検索品質を比較します：

| 戦略 | チャンクサイズ | オーバーラップ | 適するドキュメント |
|------|-------------|-------------|-----------------|
| 固定サイズ | 300トークン | 20% | FAQ、短文 |
| 階層型 | セクション単位 | なし | 構造化文書 |
| セマンティック | 意味単位 | 10% | 法律文書、技術文書 |

## パート 2: 検索の実装と最適化（20分）

### ステップ 2.1: 基本的な RetrieveAndGenerate

```bash
python3.12 rag_basic.py
```

以下のクエリで動作を確認します：
- 「契約書の解除条件について教えてください」
- 「個人情報の第三者提供に関する規制は？」
- 「従業員の残業規制について説明してください」

### ステップ 2.2: Retrieve API による検索結果の詳細確認

```bash
python3.12 rag_retrieve.py
```

Retrieve API で返される情報を確認します：
- 検索されたチャンクのテキスト
- 関連度スコア（relevance score）
- ソースドキュメントの参照情報
- メタデータ（ドキュメントタイプ、カテゴリ）

### ステップ 2.3: ハイブリッド検索の実装

`hybrid_search.py` で以下を実装します：

```bash
python3.12 hybrid_search.py
```

**ハイブリッド検索戦略:**
1. セマンティック検索: 意味的に近い文書を検索（探索的クエリ向け）
2. キーワード検索: 正確な用語・法令番号でフィルタリング（精密検索向け）
3. スコア統合: 両方のスコアを重み付けして最終ランキングを決定

### ステップ 2.4: メタデータフィルタリング

カテゴリやドキュメントタイプでフィルタリングして検索精度を向上：

```python
# 特定カテゴリのみから検索
retrieval_config = {
    "vectorSearchConfiguration": {
        "filter": {
            "equals": {"key": "category", "value": "employment_law"}
        }
    }
}
```

## パート 3: 会話型ナレッジアシスタント（15分）

### ステップ 3.1: マルチターン会話の実装

```bash
python3.12 knowledge_assistant.py
```

会話型アシスタントの機能：
- セッション ID によるコンテキスト管理
- 前の質問を参照した追加質問への対応
- 「前に聞いた契約の件で...」のような曖昧な参照の解決

### ステップ 3.2: 回答品質の制御

以下の手法で回答品質を向上させます：
- **検索結果数の調整**: `numberOfResults` パラメータ（3〜10）
- **ガードレール統合**: 不適切な質問のフィルタリング
- **引用の提示**: ソースドキュメントへの参照を回答に含める

### ステップ 3.3: アクセス制御の設計

ドキュメントレベルのアクセス制御パターン：
- 部署別（人事部は労働法のみ、法務部は全文書）
- 機密レベル別（公開、社内限定、機密）
- ロールベース（パートナー、アソシエイト、パラリーガル）

## パート 4: パフォーマンス測定と最適化（5分）

### ステップ 4.1: 検索品質の評価

RAGAS（RAG Assessment）フレームワークの概念を使用した評価：
- **Faithfulness（忠実性）**: 回答がソースに忠実か
- **Answer Relevancy（回答関連性）**: 回答が質問に対して適切か
- **Context Precision（コンテキスト精度）**: 検索結果が関連しているか

### ステップ 4.2: チャンキング最適化の効果確認

固定サイズ vs 階層型 vs セマンティックの比較結果を表示：
- 検索精度（Precision@5）
- 再現率（Recall@5）
- 平均レスポンス時間
