# モジュール 1: 基盤モデルの選択と設定 - ハンズオン手順

## パート 1: モデル評価とベンチマーク（15分）

### ステップ 1.1: プロジェクトの準備

```bash
cd ~/handson/M01-model-selection
pip install boto3 streamlit
```

### ステップ 1.2: モデルベンチマークスクリプトの実行

`benchmark.py` を使用して、3つのモデルを同一プロンプトで比較します。

```bash
python3 benchmark.py
```

このスクリプトは以下を測定します：
- **レイテンシー**: 最初のトークンまでの時間（TTFT）、合計応答時間
- **トークン使用量**: 入力/出力トークン数
- **コスト**: モデルごとの推定コスト
- **品質**: 応答の一貫性と正確性

### ステップ 1.3: 結果の確認

出力される比較テーブルを確認し、以下を議論します：
- どのモデルがどのユースケースに最適か
- コストとパフォーマンスのトレードオフ
- レイテンシー要件に基づくモデル選定基準

## パート 2: 動的モデル選択アーキテクチャの構築（15分）

### ステップ 2.1: SAM テンプレートの確認

`template.yaml` で以下のリソースが定義されています：
- API Gateway REST API
- Lambda ルーティング関数
- IAM ロール（Bedrock アクセス権限付き）

### ステップ 2.2: ルーティングロジックの実装

`lambda/router.py` のルーティングロジックを確認します：

**ルーティング戦略:**
1. **リクエスト分類**: クエリの特性（長さ、複雑性、ドメイン）を分析
2. **パフォーマンスベースルーティング**: リアルタイムのレイテンシーメトリクスに基づく選択
3. **コストベースルーティング**: 予算しきい値に基づくモデル切り替え

### ステップ 2.3: デプロイ

```bash
sam build
sam deploy --guided
```

デプロイ完了後、API Gateway のエンドポイント URL をメモします。

### ステップ 2.4: テスト

```bash
# 簡単な質問 → Nova Lite に自動ルーティング
curl -X POST <API_URL>/query \
  -H "Content-Type: application/json" \
  -d '{"query": "AWSのリージョンとは何ですか？", "complexity": "simple"}'

# 複雑な分析 → Claude Sonnet に自動ルーティング
curl -X POST <API_URL>/query \
  -H "Content-Type: application/json" \
  -d '{"query": "金融規制コンプライアンスの観点から、このドキュメントのリスク評価を行ってください", "complexity": "complex"}'
```

## パート 3: レジリエンス機能の実装（10分）

### ステップ 3.1: サーキットブレーカーの動作確認

`lambda/health_monitor.py` のサーキットブレーカー実装を確認します：

**状態遷移:**
- **Closed（通常）**: リクエストを通常通り処理
- **Open（障害）**: フェイルファスト、フォールバックモデルへ転送
- **Half-Open（回復テスト）**: 限定的なリクエストでプライマリモデルをテスト

### ステップ 3.2: 障害シミュレーション

インストラクターコントロールパネルから、特定プロバイダーの障害をシミュレートします：

```bash
# Claude を障害状態にする
curl -X POST <API_URL>/admin/simulate-failure \
  -H "Content-Type: application/json" \
  -d '{"provider": "anthropic", "failure_type": "timeout"}'
```

### ステップ 3.3: フォールバック動作の確認

障害シミュレーション中にリクエストを送信し、以下を確認します：
- サーキットブレーカーが Open 状態に遷移すること
- Nova へ自動的にフォールバックすること
- CloudWatch メトリクスに障害が記録されること

### ステップ 3.4: 回復の確認

```bash
# 障害を解除
curl -X POST <API_URL>/admin/simulate-failure \
  -H "Content-Type: application/json" \
  -d '{"provider": "anthropic", "failure_type": "none"}'
```

Half-Open → Closed への遷移を確認します。

## パート 4: コスト最適化（5分）

### ステップ 4.1: コスト追跡の確認

CloudWatch ダッシュボードで以下を確認します：
- モデルごとのトークン使用量
- 時間あたりの推定コスト
- コストアラームのしきい値設定

### ステップ 4.2: 自動モデル切り替えの確認

予算しきい値を超えた場合の動作を確認します：
- 高コストモデル（Claude Sonnet）→ 低コストモデル（Nova Lite）への自動切り替え
- 品質低下の許容範囲内であることの検証
