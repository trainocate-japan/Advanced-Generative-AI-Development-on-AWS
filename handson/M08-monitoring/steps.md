## パート 2: 応答品質のモニタリング（15分）

### ステップ 2.1: ハルシネーション検出

```bash
python3.12 hallucination_detection.py
```

検出手法：
1. **一貫性チェック**: 同じ質問への回答が矛盾していないか
2. **ソース検証**: RAG の場合、回答がソースに基づいているか
3. **エンティティ検証**: 生成された固有名詞・数値の妥当性
4. **信頼度スコア**: モデルの不確実性を数値化

### ステップ 2.2: 品質スコアダッシュボード

CloudWatch ダッシュボードに表示するメトリクス：
- Faithfulness Score（忠実性スコア）
- Answer Relevancy（回答関連性）
- Hallucination Rate（ハルシネーション率）
- Response Completeness（回答の完全性）

### ステップ 2.3: アラートルールの設定

- ハルシネーション率 > 5%: 警告
- ハルシネーション率 > 10%: 緊急（モデル切り替え検討）
- レイテンシー P95 > 10秒: 警告
- エラー率 > 1%: 緊急

## パート 3: ビジネス影響の測定（10分）

### ステップ 3.1: ビジネスメトリクスの定義

```bash
python3.12 business_metrics.py
```

3つの柱：
1. **ユーザーエンゲージメント**
   - セッション数、対話ターン数
   - 会話完了率 vs 離脱率
   - リピート利用率

2. **タスク完了**
   - 問題解決率（最初の回答で解決）
   - エスカレーション率（人間への転送）
   - 平均解決時間

3. **ROI**
   - コスト削減額（人件費との比較）
   - 処理件数の増加
   - 顧客満足度スコア（CSAT）

### ステップ 3.2: ROI 計算フレームワーク

```
ROI = (Total Benefits - Total Costs) / Total Costs × 100%

Benefits:
  - 自動解決による人件費削減: ¥X/月
  - 処理速度向上による効率改善: ¥Y/月
  
Costs:
  - Bedrock API コスト: ¥A/月
  - インフラ運用コスト: ¥B/月
  - 開発・保守コスト: ¥C/月
```

## 発展課題

1. **予測アラート**: 異常が発生する前に予測して事前対処する仕組み
2. **自動修復**: ハルシネーション検出時に自動で回答を再生成するループ
3. **コスト異常検知**: 通常パターンから逸脱したコスト増加の自動検出と対策
