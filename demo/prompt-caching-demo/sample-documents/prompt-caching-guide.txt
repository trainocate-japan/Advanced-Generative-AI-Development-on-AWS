Amazon Bedrock Prompt Caching: Complete Guide

Introduction to Prompt Caching

Prompt caching is an optional feature available on Amazon Bedrock that reduces inference response latency and input token costs. By caching portions of your context, the model can leverage the cache to skip recomputation of inputs, allowing Bedrock to share in the compute savings and lower your response latencies. This capability can significantly improve response latency by up to 85% and reduce inference costs by up to 90%, making it well-suited for applications that use repetitive, long input context.

When to Use Prompt Caching

Prompt caching on Amazon Bedrock is recommended for workloads that involve long context prompts that are frequently reused across multiple API calls. To determine if prompt caching is beneficial for your use case, you will need to estimate the number of tokens you plan to cache, the frequency of reuse, and the time between requests.

The following use cases are well-suited for prompt caching:

Chat with Document Applications
By caching the document as input context on the first request, each user query becomes more efficient, enabling simpler architectures that avoid heavier solutions like vector databases. When users upload documents and ask questions about them, it can be time consuming for the model to process the document every time the user provides input. With prompt caching, you can cache the document so that future queries containing the document don't need to reprocess it.

Coding Assistants
Reusing long code files in prompts enables near real-time inline suggestions, eliminating much of the time spent reprocessing code files. Development tools can cache entire codebases or large files, allowing for instant context-aware suggestions without repeatedly processing the same code.

Agentic Workflows
Longer system prompts can be used to refine agent behavior without degrading the end-user experience. By caching the system prompts and complex tool definitions, the time to process each step in the agentic flow can be reduced. This is particularly valuable for multi-step workflows where the same instructions and tools are used repeatedly.

Few-Shot Learning
Including numerous high-quality examples and complex instructions, such as for customer service or technical troubleshooting, can benefit from prompt caching. When you provide many examples to guide model behavior, caching these examples prevents reprocessing them with each request.

Multi-Turn Conversations
Conversations that maintain long context windows benefit from caching the conversation history. As the conversation progresses, the cached history allows the model to maintain context without reprocessing all previous messages.

How Prompt Caching Works

Amazon Bedrock creates a cache composed of cache checkpoints. These are markers that define the contiguous subsection of your prompt that you wish to cache, often referred to as a prompt prefix. These prompt prefixes should be static between requests - alterations to the prompt prefix in subsequent requests will result in cache misses.

Cache Checkpoint Requirements

Cache checkpoints have a minimum and maximum number of tokens, dependent on the specific model you're using. You can only create a cache checkpoint if your total prompt prefix meets the minimum number of tokens. For example, the Anthropic Claude 3.7 Sonnet model requires at least 1,024 tokens per cache checkpoint. That means your first cache checkpoint can be defined after 1,024 tokens and your second cache checkpoint can be defined after 2,048 tokens.

If you try to add a cache checkpoint before meeting the minimum number of tokens, your inference will still succeed, but your prefix will not be cached. The cache has a five minute Time To Live (TTL), which resets with each successful cache hit. During this period, the context in the cache is preserved. If no cache hits occur within the TTL window, your cache expires.

Supported Models and Token Requirements

The following models support prompt caching with their respective minimum token requirements:

Claude Models:
- Claude 3.7 Sonnet: 1,024 tokens minimum, 4 cache checkpoints maximum
- Claude 3.5 Sonnet v2: 1,024 tokens minimum, 4 cache checkpoints maximum
- Claude 3.5 Haiku: 2,048 tokens minimum, 4 cache checkpoints maximum
- Claude Opus 4: 1,024 tokens minimum, 4 cache checkpoints maximum
- Claude Sonnet 4: 1,024 tokens minimum, 4 cache checkpoints maximum
- Claude Haiku 4.5: 4,096 tokens minimum, 4 cache checkpoints maximum

Amazon Nova Models:
- Amazon Nova Micro: 1,024 tokens minimum, 4 cache checkpoints maximum
- Amazon Nova Lite: 1,024 tokens minimum, 4 cache checkpoints maximum
- Amazon Nova Pro: 1,024 tokens minimum, 4 cache checkpoints maximum
- Amazon Nova Premier: 1,024 tokens minimum, 4 cache checkpoints maximum

Note: Amazon Nova models support a maximum of 20,000 tokens for prompt caching and offer automatic prompt caching for all text prompts.

Simplified Cache Management for Claude Models

For Claude models, Amazon Bedrock offers a simplified approach to cache management that reduces the complexity of manually placing cache checkpoints. Instead of requiring you to specify exact cache checkpoint locations, you can use automatic cache management with a single breakpoint at the end of your static content.

When you enable simplified cache management, the system automatically checks for cache hits at previous content block boundaries, looking back up to approximately 20 content blocks from your specified breakpoint. This allows the model to find the longest matching prefix from your cache without requiring you to predict the optimal checkpoint locations.

To use this feature, place a single cache checkpoint at the end of your static content, before any dynamic or variable content. The system will automatically find the best cache match. For more granular control, you can still use multiple cache checkpoints (up to 4 for Claude models) to specify exact cache boundaries.

Pricing and Cost Optimization

When using prompt caching, you're charged at a reduced rate for tokens read from cache. Depending on the model, tokens written to cache may be charged at a rate that is higher than that of uncached input tokens. Any tokens not read from or written to cache are charged at the standard input token rate for that model.

Cost Optimization Strategies:

1. Identify Opportunities for Caching
Review your workload for repeated prompt components. Verify that prompts meet minimum token requirements. Assess potential cost savings from reduced token rates by calculating the break-even point where cache write costs are offset by cache read savings.

2. Structure Prompts for Maximum Cache Efficiency
Place static content at the beginning of prompts. Keep variable content at the end after cache checkpoints. Ensure cached sections remain unchanged between requests to maximize cache hits.

3. Monitor Caching Metrics
Track cache hit and miss rates to understand effectiveness. Monitor token costs for cached versus uncached content. Analyze latency improvements to quantify performance benefits. Use these metrics to optimize checkpoint placement and prompt structure.

4. Balance Cache Write Costs with Read Savings
Consider the frequency of reuse when deciding what to cache. For content used only once or twice, caching may not be cost-effective due to the premium write cost. For content reused many times, the reduced read costs quickly offset the initial write premium.

Implementation with Converse API

The Converse API provides advanced and flexible options for implementing prompt caching in multi-turn conversations. You can place cache checkpoints in the messages, system, or tools fields of a request.

Example: Caching Messages
You can cache user messages that contain large amounts of context, such as images or long text passages. Place a cachePoint after the content you want to cache:

{
  "messages": [
    {
      "role": "user",
      "content": [
        {
          "image": {
            "bytes": "base64_encoded_image_data"
          }
        },
        {
          "text": "What's in this image?"
        },
        {
          "cachePoint": {
            "type": "default"
          }
        }
      ]
    }
  ]
}

Example: Caching System Prompts
System prompts that define model behavior are ideal candidates for caching since they typically remain constant across requests:

{
  "system": [
    {
      "text": "You are an expert assistant specializing in cloud architecture. You provide detailed, accurate information about AWS services and best practices. Always cite official documentation when possible."
    },
    {
      "cachePoint": {
        "type": "default"
      }
    }
  ]
}

Example: Caching Tool Definitions
When using tools with the model, cache the tool definitions to avoid reprocessing them with each request:

{
  "toolConfig": {
    "tools": [
      {
        "toolSpec": {
          "name": "get_weather",
          "description": "Get current weather information for a location",
          "inputSchema": {
            "json": {
              "type": "object",
              "properties": {
                "location": {
                  "type": "string",
                  "description": "City name or coordinates"
                }
              },
              "required": ["location"]
            }
          }
        }
      },
      {
        "cachePoint": {
          "type": "default"
        }
      }
    ]
  }
}

Understanding Cache Metrics

The model response includes two fields specific to prompt caching:

CacheReadInputTokens: The number of tokens read from the cache. These tokens are charged at a reduced rate, providing cost savings.

CacheWriteInputTokens: The number of tokens written to the cache in this request. These tokens may be charged at a premium rate but enable future cost savings.

By monitoring these metrics, you can understand the effectiveness of your caching strategy and optimize accordingly.

Best Practices for Prompt Caching

1. Meet Minimum Token Requirements
Ensure your cached content meets the minimum token requirement for your chosen model. Content below the minimum will not be cached, even if you place a cache checkpoint.

2. Keep Cached Content Static
The cached portion of your prompt should remain unchanged between requests. Any modification to the cached content will result in a cache miss and require reprocessing.

3. Place Cache Checkpoints Strategically
Position cache checkpoints after static content and before variable content. For multiple checkpoints, consider caching sections that change at different frequencies separately.

4. Monitor Cache TTL
The cache expires after 5 minutes of inactivity. For applications with sporadic usage, consider the cache TTL when evaluating cost effectiveness.

5. Use Simplified Cache Management When Appropriate
For Claude models, consider using the simplified cache management approach with a single checkpoint. This reduces complexity while still providing cache benefits.

6. Test and Iterate
Experiment with different cache checkpoint placements and monitor the results. Use cache metrics to refine your approach and maximize cost savings and performance improvements.

Common Pitfalls to Avoid

1. Caching Content Below Minimum Tokens
Placing cache checkpoints before reaching the minimum token requirement wastes the checkpoint without providing any benefit.

2. Modifying Cached Content
Changing the content before a cache checkpoint between requests defeats the purpose of caching and results in cache misses.

3. Over-Caching Variable Content
Caching content that changes frequently leads to constant cache misses and wasted cache write costs.

4. Ignoring Cache Metrics
Failing to monitor cache hit rates and token costs prevents optimization and may result in higher costs than expected.

5. Not Considering Cache TTL
For applications with long periods between requests, the cache may expire before being reused, negating the benefits.

Advanced Caching Strategies

Multiple Cache Checkpoints
Use multiple cache checkpoints to cache sections that change at different frequencies. For example, cache a system prompt with one checkpoint, a large document with another, and conversation history with a third.

Cross-Region Inference with Caching
Prompt caching can be used in conjunction with cross-region inference. Cross-region inference automatically selects the optimal AWS Region within your geography to serve your inference request. At times of high demand, these optimizations may lead to increased cache writes.

Prompt Management Integration
When creating or modifying prompts in Amazon Bedrock Prompt Management, you can enable prompt caching. Depending on the model, you can cache system prompts, system instructions, and messages. This provides a centralized way to manage cached prompts across your organization.

Automatic Prompt Caching for Amazon Nova
Amazon Nova models offer automatic prompt caching for all text prompts, including User and System messages. This mechanism can provide latency benefits when prompts begin with repetitive parts, even without explicit configuration. However, to unlock cost savings and ensure more consistent performance benefits, it's recommended to opt in to Explicit Prompt Caching.

Measuring Success

To evaluate the effectiveness of your prompt caching implementation, track these key metrics:

Cache Hit Rate: Percentage of requests that successfully use cached content. Higher rates indicate better cache effectiveness.

Token Cost Reduction: Compare total token costs with and without caching. Calculate the percentage reduction in costs.

Latency Improvement: Measure the reduction in response time for cached requests. Improvements of up to 85% are possible.

Break-Even Analysis: Calculate how many cache hits are needed to offset the cache write costs. This helps determine if caching is cost-effective for your use case.

Cache Expiration Rate: Monitor how often caches expire before being reused. High expiration rates may indicate that caching isn't suitable for your usage pattern.

Conclusion

Prompt caching on Amazon Bedrock is a powerful feature for optimizing both cost and performance in applications with repetitive, long-context prompts. By understanding when to use caching, how to implement it effectively, and how to monitor its performance, you can significantly reduce inference costs and improve user experience.

The key to successful prompt caching is identifying the right use cases, structuring prompts appropriately, and continuously monitoring and optimizing based on cache metrics. With proper implementation, prompt caching can reduce costs by up to 90% and improve latency by up to 85%, making it an essential tool for production generative AI applications.
